# Changelog

All notable changes to ExcelMapper (NuGet package [`ExcelDataReader.Mapping`](https://www.nuget.org/packages/ExcelDataReader.Mapping/)) are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/).

## [4.0.0] - Unreleased

4.0 makes mapping faster and more predictable, and adds ways to read real-world spreadsheets:

- **Read messy sheets:** find a heading below titles and notes (`FindHeading`), read part of a sheet or several tables on one sheet (`Region`), and report every invalid cell in a file instead of stopping at the first (`ReadRowResults`, or `ReadRows` with an `IExcelErrorSink`, which allocates nothing per problem).
- **Map more types:** records and constructor-only types, row numbers, the columns no other member reads, and dates and times written as text in more formats.
- **Native AOT:** a source generator in the package writes an `ExcelMappingContext`, so apps compiled with native AOT map rows without reflection or warnings.
- **Extend it simply:** typed converters, transformers, fallbacks and column selectors replace the old low-level types.
- **Faster:** compared with 3.0.3, mapping an auto-mapped 10-member class takes less than half the time beyond reading the file (20% less in all, as ExcelDataReader reading the file is most of it), and ExcelMapper's own allocations for it are 93% lower; invalid cells with a fallback map 9 times faster, as they no longer throw and catch exceptions; and auto-mapping a type is nearly 4 times faster. See the [benchmarks](benchmarks/README.md#40-compared-with-303).

4.0 contains breaking changes. Most code compiles unchanged, but some behaviour changed: see [Migrating to 4.0](docs/migrating-to-4.0.md) for what to check when upgrading from 3.x.

### Breaking changes

- `object` and `IConvertible` members, and `object` values in dictionaries, `ExpandoObject` and non-generic collections, receive the value as Excel stores it (`double`, `DateTime`, `bool`, `string`, ...) instead of its text. ([#124](https://github.com/hughbe/excel-mapper/pull/124))
- Blank rows after the last row with a value aren't rows, in workbooks as in CSV files: formatted empty rows below a table are no longer mapped, which made `int` and other non-nullable members throw, or gave rows of empty objects. Blank rows between rows with values are mapped as before. A one-column sheet whose last rows are empty ends at its last value. ([#223](https://github.com/hughbe/excel-mapper/pull/223))
- Text is parsed, and numbers and dates are converted to text, with the invariant culture by default instead of the current culture of the thread reading the rows, so the same file gives the same values on every machine (on a machine set to German, `1.5` was read as fifteen). The same goes for heading cells that are numbers or dates, which name their columns. Set `ExcelImporterConfiguration.Culture` to the file's culture, or to `CultureInfo.CurrentCulture` for the machine's. ([#205](https://github.com/hughbe/excel-mapper/pull/205), [#222](https://github.com/hughbe/excel-mapper/pull/222))
- Dates no longer depend on the machine's time zone ([#217](https://github.com/hughbe/excel-mapper/pull/217)):
  - Text with an offset (`2024-03-04T10:30:15Z`, `+01:00`) mapped to `DateTime` is converted to UTC (`Kind` `Utc`) instead of the machine's local time. Text without an offset is unchanged (`Kind` `Unspecified`).
  - Cells Excel stores as dates, and text without an offset, mapped to `DateTimeOffset` are UTC (`+00:00`) instead of having the machine's local offset. `[ExcelOffset]` and `WithOffset` choose another offset, and now apply to text without an offset too. Text with its own offset keeps it.
- `WithConverter` replaces the built-in conversion (and any earlier converter) instead of being tried after it, so the converter is used for every cell that isn't empty, whatever the member's type. Before, it was only used for values the built-in conversion couldn't convert for numbers, dates, enums and most other types, but for every value of strings. ([#154](https://github.com/hughbe/excel-mapper/pull/154))
- A fractional number (such as `2.7`) mapped to an integer type is invalid instead of being truncated (.NET 8) or rounded (netstandard), matching text cells. ([#127](https://github.com/hughbe/excel-mapper/pull/127))
- `ReadRow` and `TryReadRow` read the heading first if it hasn't been read, like `ReadRows`, instead of mapping the heading row as data. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- Sheet names are matched case-insensitively by `ReadSheet(name)` and `TryReadSheet(name, ...)`, as in Excel. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Error messages give Excel cell addresses and one-based rows (`at cell B11`, `on row 11`) instead of zero-based row indexes. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- `ExcelRange` is a `readonly struct`; `default(ExcelRange)` (and the value `TryParse` returns on failure) means every row and column instead of an empty range; `Parse` rejects non-ASCII letters, signs, and rows or columns beyond Excel's limits. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- With a `DataRange` that doesn't start at the first column, `ExcelHeading.GetColumnIndex` and `GetColumnName` use positions in the sheet rather than in the range. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Splitting a cell with a trailing separator (`"a,b,"`) includes the trailing empty value, as `string.Split` does, for arrays and lists alike; an empty cell gives no values. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Reading a member whose column name matches more than one column in the heading (such as two columns named "Name", or "Name" and "name") throws an `ExcelMappingException` naming both columns, instead of silently reading the first. Choose one by letter or index, or rename a column. ([#207](https://github.com/hughbe/excel-mapper/pull/207))
- Reading rows with a class map that maps no members, such as an auto-mapped type whose properties all have private setters, throws an `ExcelMappingException` naming the type, instead of giving an empty object for every row. This includes nested types and collections of them. ([#208](https://github.com/hughbe/excel-mapper/pull/208))
- `ReadRowResults` throws when it's called if the heading doesn't have a column the type needs, with the message `ValidateHeading` gives, instead of reporting the missing column as an error of every row. ([#209](https://github.com/hughbe/excel-mapper/pull/209))
- A sheet takes the importer's settings when it starts reading, so changing them while its rows are read only affects sheets read afterwards, instead of the following rows. ([#182](https://github.com/hughbe/excel-mapper/pull/182))
- A class map can't be changed once rows have been read with it (by `ReadRows`, `ReadRow`, `ReadRowResults`, `ValidateHeading` or `FindHeading`): calling `Map` or a fluent method on it, or on a map of one of its members, throws an `InvalidOperationException` instead of changing how the following rows are read. Register a new class map to read differently. ([#185](https://github.com/hughbe/excel-mapper/pull/185))
- `RegisterClassMap` replaces a class map that auto-mapping registered implicitly instead of throwing. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- The low-level extension types are internal, replaced by four extension points: `ICellConverter<T>` (convert a cell), `ICellTransformer` (change a cell before it's converted), `ICellFallback<T>` (the value of an empty or invalid cell) and `IColumnSelector` (choose columns). Attributes, class maps and the fluent methods are unchanged, so most code compiles as before. See [Extension types](docs/migrating-to-4.0.md#extension-types) for what replaces each type.
  - Conversion: `ICellMapper`, `CellMapperResult`, `ReadCellResult`, the mappers in `ExcelMapper.Mappers`, `WithMappers`, `[ExcelMapper]` and the `WithConverter` overload whose delegate takes a `ReadCellResult`. `WithConverter(value => ...)` is a method of a member's map, so a delegate that only throws, or returns a type convertible to the member's, compiles. ([#164](https://github.com/hughbe/excel-mapper/pull/164))
  - Transformers and fallbacks: `Abstractions.ICellTransformer`, `IFallbackItem`, the types in `ExcelMapper.Fallbacks` and `ExcelMapper.Transformers`, `WithFallbackItem`, `WithEmptyFallbackItem` and `WithInvalidFallbackItem`; the attributes no longer accept the old types. ([#164](https://github.com/hughbe/excel-mapper/pull/164))
  - Pipelines: `IValuePipeline` and `IValuePipeline<T>`, and the pipelines' `Mappers`, `Transformers`, `EmptyFallback` and `InvalidFallback` properties. A member's map is a `ValueMap<T>`, and the elements or values of a collection are an `ElementMap<T>` (the collection maps' `Pipeline`). Both derive from `ValuePipeline<T, TSelf>`, whose value methods return the map they're called on; the methods for particular types, such as `WithFormats`, are in `ValuePipelineExtensions` (renamed from `IValuePipelineExtensions`). `ValuePipeline` and `ValuePipeline<T>`, which had no public members, are internal. `WithElementMap`/`WithValueMap` take an `Action<ElementMap<T>>` that configures the map's own elements or values, so expression lambdas such as `e => e.WithTrim()` compile unchanged; a block lambda that returns the map must drop its `return` ([#236](https://github.com/hughbe/excel-mapper/pull/236)). ([#163](https://github.com/hughbe/excel-mapper/pull/163), [#164](https://github.com/hughbe/excel-mapper/pull/164), [#170](https://github.com/hughbe/excel-mapper/pull/170), [#219](https://github.com/hughbe/excel-mapper/pull/219))
  - Columns: the readers and reader factories (`ExcelMapper.Readers`, `ICellReader`, `ICellReaderFactory`, `ICellsReader`, `ICellsReaderFactory`), `IExcelColumnMatcher`, `WithReaderFactory` and the matcher overloads; use `IColumnSelector` and `WithColumns(selector)`. ([#162](https://github.com/hughbe/excel-mapper/pull/162))
  - Maps: `IMap`, `IToOneMap`, `IOneToOneMap`, `IManyToOneMap`, `ExcelPropertyMap`, `ExcelClassMap.Properties`, the indexer maps, `AutoMapper`, the maps' constructors and `TryGetValue` methods, and the extension classes `IOneToOneMapExtensions`, `IManyToOneMapExtensions` and `IToOneMapExtensions`, whose column methods are now methods of the maps. `TryGetClassMap` returns an `ExcelClassMap`, and `RegisterClassMap(Type, IMap)` is removed: use `RegisterClassMap(classMap)`. ([#162](https://github.com/hughbe/excel-mapper/pull/162), [#165](https://github.com/hughbe/excel-mapper/pull/165))
  - Collections: the collection factories (`ExcelMapper.Factories`, `IEnumerableFactory<T>`, `IDictionaryFactory<TKey, TValue>`, `IMultidimensionalArrayFactory<T>`): ExcelMapper creates the collection for a member's type. ([#160](https://github.com/hughbe/excel-mapper/pull/160))
  - `MappingDictionaryMapperBehavior` moved to the `ExcelMapper` namespace, and is renamed `MappingDictionaryBehavior`. ([#164](https://github.com/hughbe/excel-mapper/pull/164), [#169](https://github.com/hughbe/excel-mapper/pull/169))
- Methods and properties are renamed or removed to make the API consistent and remove traps, with the replacement for each in [Renamed and removed methods](docs/migrating-to-4.0.md#renamed-and-removed-methods). ([#191](https://github.com/hughbe/excel-mapper/pull/191))
  - `Map(p => p.Status, ignoreCase: true)`, which compiled for any struct and threw at run time for types other than enums, is `.WithIgnoreCase()` on enum members and elements.
  - `RegisterClassMap(Type, ExcelClassMap)`, which let a class map be registered for a different type, is removed: `RegisterClassMap(classMap)` uses the map's own type. `RegisterClassMapsInNamespace` is a method of `ExcelImporterConfiguration`, and `ExcelImporterExtensions` is removed.
  - `ExcelImporter.Reader` is internal: moving the reader shared by the importer's sheets broke their positions. `ExcelClassMap` is abstract and only `ExcelClassMap<T>` can derive from it, as a non-generic class map couldn't map any members.
  - The static `ExcelImporter.ReadRows<T>` has an overload for each combination of path or stream, file type and configuration instead of optional parameters, so `ReadRows<T>(path, c => ...)` reads an Excel file.
  - `WithValueFallback` is `WithFallback`; `ValueMap.WithColumnNameMatching(params string[])` is `WithColumnNames`; `Optional` and `PreserveFormatting` are read-only (use `MakeOptional()` and `MakePreserveFormatting()`); the collection and dictionary maps' `Pipeline` is internal (use `WithElementMap` and `WithValueMap`); the `ExcelRange(string)` constructor is removed (use `ExcelRange.Parse`).
  - Attributes take options as named properties rather than constructor arguments: `[ExcelColumnName("Name", Comparison = StringComparison.Ordinal)]`, `[ExcelColumnNames("A", "B", Comparison = ...)]`, and `[ExcelColumnMatching(pattern, RegexOptions = ...)]` and `[ExcelColumnsMatching(pattern, RegexOptions = ...)]` (the new `RegexOptions` property). ([#218](https://github.com/hughbe/excel-mapper/pull/218))
  - `TryGetClassMap<T>` gives an `ExcelClassMap<T>` rather than an `ExcelClassMap`. ([#218](https://github.com/hughbe/excel-mapper/pull/218))
  - `ExcelImporter`, `ExcelImporterConfiguration`, `ExcelSheet`, `ExcelHeading`, `ValueMap<T>`, `CollectionMap<T>` and `DictionaryMap<TKey, TValue>` are sealed: none had members to override, and the others can only be created by ExcelMapper. ([#219](https://github.com/hughbe/excel-mapper/pull/219))
  - List parameters are `params T[]` or `IEnumerable<T>` everywhere, instead of also `IReadOnlyList<T>`. The column attributes' `Index`, `Indices`, `Name` and `Names` are read-only, and the attributes are sealed except `ExcelColumnIndexAttribute`.
- Types are renamed to say what they are: `OneToOneMap<T>` is `ValueMap<T>`, `ManyToOneEnumerableMap<T>` is `CollectionMap<T>`, `ManyToOneDictionaryMap<TKey, TValue>` is `DictionaryMap<TKey, TValue>` (the methods of `OneToOneMapExtensions` are methods of the maps); `FallbackStrategy` is `EmptyValueStrategy`, with `Error` and `DefaultValue` instead of `ThrowIfPrimitive` and `SetToDefaultValue`; `[ExcelUri]` is `[ExcelUriKind]`; `ExcelImporterUtils.RegisterClassMapsInNamespace` is `ExcelImporterConfiguration.RegisterClassMapsInNamespace`; and `WithConverter(value => ...)` takes a `Func<string?, T>` instead of `ConvertUsingSimpleMapperDelegate<T>`. Code that uses `var` and lambdas compiles unchanged. See [Renamed types](docs/migrating-to-4.0.md#renamed-types). ([#169](https://github.com/hughbe/excel-mapper/pull/169))
- `WithFallback` (was `WithValueFallback`), `WithEmptyFallback` and `WithInvalidFallback` take a value of the member's type instead of an `object`, so a value of the wrong type is a compile error instead of an `InvalidCastException` when rows are read. ([#170](https://github.com/hughbe/excel-mapper/pull/170))
- Two helper types made public by accident are internal: `CallerArgumentExpressionAttribute` on the netstandard builds (a polyfill, which the compiler ignored) and `ExcelMapper.Utilities.StringComparerUtilities`. ([#167](https://github.com/hughbe/excel-mapper/pull/167))
- `ExcelClassMap<T>.MapList` is renamed `MapCollection`, as it maps any collection type, such as `HashSet<T>`, not only lists. ([#225](https://github.com/hughbe/excel-mapper/pull/225))
- `ValueMap.WithColumnNameMatching` is renamed `WithColumnMatching`, as `[ExcelColumnMatching]` is named, and `ExcelHeading.GetFirstColumnMatchingIndex` and `TryGetFirstColumnMatchingIndex` are overloads of `GetColumnIndex` and `TryGetColumnIndex` taking a predicate. `GetColumnIndex`'s error lists the heading's columns as other errors do. ([#234](https://github.com/hughbe/excel-mapper/pull/234))
- With `ValidateDataAnnotations` on, `ReadRows` and `ReadRow` throw an `ExcelMappingException` for a failed annotation, naming the row and member, with the `ValidationException` as its `InnerException`, as `ReadRowResults` reports it, instead of a bare `ValidationException` that didn't say which row failed. ([#235](https://github.com/hughbe/excel-mapper/pull/235))
- Using an importer, or its sheets and regions, after disposing it (or after closing the `IExcelDataReader` it was created with) throws an `ObjectDisposedException` instead of an `ExcelMappingException`. ([#237](https://github.com/hughbe/excel-mapper/pull/237))

### Added

- `ExcelSheet.ReadRows<T>(IExcelErrorSink)` (and on `ExcelRegion`, and with a class map) returns the rows without problems and gives each problem to the sink as an `ExcelMappingError`, without creating an exception for it unless the sink calls `ToException()`. Checking a large file with many invalid cells then allocates nothing per invalid cell. ([#211](https://github.com/hughbe/excel-mapper/pull/211))
- A source generator, in the package, writes `ExcelMappingContext`s: `[ExcelMappable(typeof(Employee))] partial class AppMappingContext : ExcelMappingContext { }` registers `Employee` and every type its members use, and adds an `Employee` property with its class map and a `Default` instance, so `sheet.ReadRows(AppMappingContext.Default.Employee)` works with native AOT. It reports a context that isn't `partial` (EXM001), doesn't derive from `ExcelMappingContext` (EXM002), declares `RegisterTypes` (EXM003), or names an open generic type (EXM004). ([#200](https://github.com/hughbe/excel-mapper/pull/200))
- `ExcelMappingContext` gives class maps for native AOT: it registers the types rows are mapped to and the types of their members with an `ExcelTypeRegistrar` (`Row<T>()`, `Type<T>()`, `Nullable<T>()`, `Enum<TEnum>()`, `Collection<TCollection, TElement>()`, `Array<TElement>()`, `Dictionary<TDictionary, TKey, TValue>()`, `Parsable<T>()`, `ParsableClass<T>()`), and `GetClassMap<T>()` auto-maps a row type with them. Every reading method of `ExcelSheet` and `ExcelRegion` (`ReadRows`, `ReadRow`, `TryReadRow`, `ReadRowResults`, `ValidateHeading`, `TryValidateHeading`, `FindHeading`, `TryFindHeading`) also takes an `ExcelClassMap<T>`, which it reads with rather than looking one up or auto-mapping, without trimming or AOT warnings. ([#199](https://github.com/hughbe/excel-mapper/pull/199))
- On the netstandard builds, `WithNumberStyle` and `WithFormatProvider` for the built-in number types (`int`, `decimal`, `double` and so on, and their nullable versions), as on .NET 8. `WithIgnoreCase()` works on an enum collection's elements too, and collections split from one cell take `WithColumnLetter("B")`. ([#191](https://github.com/hughbe/excel-mapper/pull/191))
- `CollectionMap<T>.WithSplitOptions(StringSplitOptions)` removes empty values or trims values when splitting a cell, as `[ExcelSeparators(Options = ...)]` does. ([#218](https://github.com/hughbe/excel-mapper/pull/218))
- `ExcelClassMap<T>.AutoMap()` maps every member auto-mapping would, except members already mapped, so a class map can start from auto-mapping and change only some members: `RegisterClassMap<T>(c => { c.AutoMap(); c.Map(e => e.Name).WithColumnName("Full Name"); })`. It replaces 3.x's public `AutoMapper.TryCreateClassMap`. ([#177](https://github.com/hughbe/excel-mapper/pull/177))
- The `NativeAot` benchmarks compare mapping with a generated `ExcelMappingContext` under the JIT and as a native AOT app. ([#203](https://github.com/hughbe/excel-mapper/pull/203))
- The `Mapping` benchmarks cover auto-mapping, class maps, invalid values, typed numbers, collections, records, row results, typed converters and regions, and can run against an earlier version of the package to compare (`EXCELMAPPER_VERSION=3.0.3`). ([#173](https://github.com/hughbe/excel-mapper/pull/173))
- The elements and values of collections (`WithElementMap`, `WithValueMap`) take the same value methods as a member's map, including converters and fallbacks for a nullable element's underlying type. `WithMapping` accepts a dictionary whose values derive from the member's type, such as a `Dictionary<string, string>` for a `string?` member. ([#170](https://github.com/hughbe/excel-mapper/pull/170))
- Reading a region gives converters, transformers, fallbacks, column selectors and errors the sheet the region was created from, with the region's heading in `CellContext.Heading` and `ColumnSelectorContext.Heading`, rather than a sheet created for the region. ([#174](https://github.com/hughbe/excel-mapper/pull/174))
- The package includes XML documentation, so the API's documentation shows in IntelliSense. ([#167](https://github.com/hughbe/excel-mapper/pull/167))
- `WithFormats`, `WithFormatProvider`, `WithOffset` and `WithNumberStyle` on a member's map return the map itself, so other methods such as `MakeOptional()` chain after them; nullable members take converters and fallbacks for their underlying type: `WithConverter(value => int.Parse(value))`, `WithConverter(ICellConverter<int>)`, `WithEmptyFallback(ICellFallback<int>)` and `WithInvalidFallback(ICellFallback<int>)` on an `int?` member. ([#159](https://github.com/hughbe/excel-mapper/pull/159))
- `IColumnSelector` chooses the columns a member is read from, once for each sheet, from a `ColumnSelectorContext` (the sheet and the heading of the rows being read), with a description for error messages. Set it with `WithColumns(selector)`, `[ExcelColumnMatching(typeof(...))]` or `[ExcelColumnsMatching(typeof(...))]`: a single value reads the first column chosen, a collection or dictionary all of them. ([#158](https://github.com/hughbe/excel-mapper/pull/158))
- `ICellTransformer` (in the `ExcelMapper` namespace) changes a cell's value before it's converted, and can return a typed value (`new CellValue(number)`); `ICellFallback<T>` gives the value of an empty or invalid cell with the cell's value, context and the exception, without boxing. Set them with `WithTransformers(...)`, `WithEmptyFallback(fallback)`, `WithInvalidFallback(fallback)`, `[ExcelTransformer]`, `[ExcelEmptyFallback]` and `[ExcelInvalidFallback]`; `CellValue` has constructors for numbers, booleans, dates and durations. ([#156](https://github.com/hughbe/excel-mapper/pull/156))
- `ICellConverter<T>` converts cells to a member's type with the typed cell value (`CellValue`: numbers, dates and booleans from Excel files aren't converted to text) and where the cell is (`CellContext`: sheet, heading, row, column, cell address, member and culture; `new ExcelMappingException(message, context)` reports the cell as an error), returning a `CellConversionResult<T>` (`Success`, `Invalid` with an optional exception created only if it's used, or `NotHandled`). Set it with `[ExcelConverter(typeof(...))]` or `WithConverter(converter)`; a converter for `T` also converts `T?` members, and for a collection it converts each element. Converters run without boxing. ([#155](https://github.com/hughbe/excel-mapper/pull/155))
- Records and types without a parameterless constructor are created through a constructor whose parameters match mapped members; read-only properties can be mapped through constructor parameters. ([#118](https://github.com/hughbe/excel-mapper/pull/118))
- `[ExcelRowNumber]` and `MapRowNumber(...)` set a member to the row's number, as Excel shows it (`MapRowNumber` returns nothing, as there's nothing to configure; [#218](https://github.com/hughbe/excel-mapper/pull/218)); `[ExcelExtraColumns]` and `MapExtraColumns(...)` fill a dictionary with the columns no other member reads. ([#136](https://github.com/hughbe/excel-mapper/pull/136))
- `ExcelSheet.ReadRowResults<T>()` reports every invalid cell in every row instead of stopping at the first. ([#126](https://github.com/hughbe/excel-mapper/pull/126))
- `ExcelSheet.Region(...)` and `ExcelRegion` read a block of a sheet with its own heading, to read part of a sheet or several tables on one sheet; `WithHeadingAt`, `WithoutHeading` and `WithHeadingSearch` choose the heading. ([#144](https://github.com/hughbe/excel-mapper/pull/144))
- `ExcelSheet.FindHeading<T>()` and `TryFindHeading<T>()` find the heading row of sheets with titles, notes or blank rows above it, as the first row with the columns `T` needs. ([#140](https://github.com/hughbe/excel-mapper/pull/140))
- `ExcelSheet.ValidateHeading<T>()` and `TryValidateHeading<T>()` report every missing column before reading rows. ([#128](https://github.com/hughbe/excel-mapper/pull/128))
- `ExcelImporter.ReadRows<T>(path or stream)` reads the first sheet in one call. ([#129](https://github.com/hughbe/excel-mapper/pull/129))
- `new ExcelImporter(path)` and `ExcelImporter.ReadRows<T>(path)` read a file whose extension is `.csv`, `.tsv` or `.txt` as CSV, instead of failing with a `HeaderException`; other files are still read as workbooks. ([#215](https://github.com/hughbe/excel-mapper/pull/215))
- `[ExcelColumnLetter("C")]` and `.WithColumnLetter("C")` map columns by Excel letter. ([#129](https://github.com/hughbe/excel-mapper/pull/129))
- `ExcelImporterConfiguration.Culture` sets the culture used for parsing and converting values to text (default: invariant). It's given to the built-in conversions rather than set as the thread's culture, so converters and fallbacks run in the caller's culture and get the importer's from `CellContext.FormatProvider`. ([#127](https://github.com/hughbe/excel-mapper/pull/127), [#179](https://github.com/hughbe/excel-mapper/pull/179), [#205](https://github.com/hughbe/excel-mapper/pull/205))
- `ExcelImporterConfiguration.IgnoreSeparatorsInColumnNames` matches `FirstName` to columns such as "First Name"; errors for a missing column suggest a column whose name differs only by spaces, underscores, hyphens or dots. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- `ExcelImporter` constructors that take an `ExcelReaderConfiguration` (passwords, CSV separators, fallback encodings). ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- `[ExcelOffset("+00:00")]` and `.WithOffset(TimeSpan)` choose the offset of `DateTimeOffset` members, for dates without one. ([#131](https://github.com/hughbe/excel-mapper/pull/131), [#217](https://github.com/hughbe/excel-mapper/pull/217))
- `ExcelMappingException.CellAddress`, `ColumnName` and `Member`. ([#117](https://github.com/hughbe/excel-mapper/pull/117), [#130](https://github.com/hughbe/excel-mapper/pull/130))
- `ExcelRange` equality operators, `ToString()` (an Excel address such as `"A1:B10"`) and `$` absolute references. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- `WithColumnsMatching(Func<string, bool>)`, `WithColumnsMatching(Regex)` and `WithColumnMatching(Regex)`. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- Dates and times written as text (in CSV files, for example) are accepted in more formats by default: ISO 8601 (`2024-03-04`, `2024-03-04T10:30:15Z`) and the culture's short date and short date and time for `DateTime` and `DateTimeOffset`, ISO 8601 for `DateOnly`, and the culture's long time and 24-hour times for `TimeOnly`. Set formats with `[ExcelFormats]` or `WithFormats` to accept only those. ([#139](https://github.com/hughbe/excel-mapper/pull/139))
- Numbers in cells without a date format map to `DateTime`, `DateTimeOffset` and `DateOnly` (Excel serial dates), `TimeOnly` (fraction of a day) and `TimeSpan` (days); time cells map to `TimeSpan`; `bool` accepts "yes" and "no". ([#123](https://github.com/hughbe/excel-mapper/pull/123))
- Sheets without a heading can be auto-mapped when columns aren't looked up by name, for example primitives or `[ExcelColumnIndex]` members. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- `ExcelMappingException` is thrown, instead of `NullReferenceException`, when an empty value can't be assigned to a non-nullable value type. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Trimming annotations for the net8.0 build: the type passed to `ReadRows<T>`, `RegisterClassMap<T>` and `ExcelClassMap<T>`, and types given in attributes, are kept by the trimmer, so mapping works in trimmed apps; reflection-based APIs are marked `[RequiresUnreferencedCode]`/`[RequiresDynamicCode]` so trimmed and AOT apps get warnings where they call them. See [Trimming and Native AOT](docs/trimming.md). ([#138](https://github.com/hughbe/excel-mapper/pull/138))
- An index or dictionary key in a mapping expression can be a variable or field the expression captures, such as a loop variable in `for (var i = 0; i < 4; i++) c.Map(p => p.Quarters[i])`, as well as a constant. ([#240](https://github.com/hughbe/excel-mapper/pull/240))

### Changed

- Error messages are clearer ([#209](https://github.com/hughbe/excel-mapper/pull/209)):
  - A missing column's message lists the columns the heading has: `Can't find column "Value" for member "Value" in sheet "People". The heading's columns are "Valeu", "Other".` It no longer gives a row, as the column is missing from the sheet, and its `RowIndex` is -1.
  - An empty cell says so: `The cell is empty, but member "Age" of type int can't be empty ...`, with what to do. A number that's too large for its type, or has a fraction for an integer type, says which.
  - Types are named as in C# (`int`, `int?`, `List<string>`, `Employee`) rather than `System.Int32`, in every message, including those about class maps, attributes, constructors and circular references, and without quotes. ([#213](https://github.com/hughbe/excel-mapper/pull/213))
  - When a constructor throws, its message follows the row: `Could not create an instance of type Employee on row 2. Salary can't be negative.` ([#213](https://github.com/hughbe/excel-mapper/pull/213))
  - Messages for a CSV file, whose sheet has no name, don't end with `in sheet ""`.
  - Reading an empty sheet that has a heading says the sheet is empty, rather than `Sheet "Empty" does not have row 0`; rows in messages are one-based, as Excel shows them.
- On .NET 8, a class that implements `IParsable<T>` or `INumberBase<T>` is parsed from its cell even if it has no public parameterless constructor (for example `IPAddress`, or a record with a constructor), rather than mapped through its members; its `Parse` method creates it. ([#201](https://github.com/hughbe/excel-mapper/pull/201))
- A value given by `[ExcelMappingDictionary]` that isn't of the member's type is reported when the class map is created, with an `ExcelMappingException` naming the attribute and the member, instead of an `InvalidCastException` when that text is read. ([#168](https://github.com/hughbe/excel-mapper/pull/168))
- The inner exception of the `ExcelMappingException` for an invalid number, date, `Guid`, `bool`, enum or `Uri` has ExcelMapper's own message, naming the value, the type and any formats (for example `The value "abc" isn't a valid int.`), instead of the .NET parser's message. Its type is unchanged. ([#157](https://github.com/hughbe/excel-mapper/pull/157))
- Code page encodings are registered automatically; `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` is no longer needed. The netstandard builds now depend on `System.Text.Encoding.CodePages`. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- Trimming only changes text, so cells Excel stores as dates or numbers keep their type. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- A converter, fallback, transformer or column selector given by an attribute (`[ExcelConverter]`, `[ExcelEmptyFallback]`, `[ExcelInvalidFallback]`, `[ExcelTransformer]`, `[ExcelColumnMatching]`, `[ExcelColumnsMatching]`) that can't be created with the attribute's constructor arguments, or whose constructor throws, is reported with an `ExcelMappingException` naming the type, the attribute and the member, instead of a `MissingMethodException` or `TargetInvocationException`. ([#188](https://github.com/hughbe/excel-mapper/pull/188))
- Exceptions thrown by a constructor are wrapped in `ExcelMappingException`. ([#118](https://github.com/hughbe/excel-mapper/pull/118))
- Building an `ExcelMappingException` message no longer reads the sheet's heading. ([#130](https://github.com/hughbe/excel-mapper/pull/130))
- Numbers are parsed the same way on every build. On the netstandard builds, `[ExcelNumberStyle]` now takes effect (previously it was ignored there), and text is parsed with `NumberStyles.Number`, so thousands separators such as `"1,234"` are accepted for integers as they were on .NET 8. Floating-point types also accept exponents such as `"1E5"` on every build (previously only on netstandard). ([#135](https://github.com/hughbe/excel-mapper/pull/135))
- Updated ExcelDataReader to 3.9.0 and ExcelNumberFormat to 1.2.0. ([#115](https://github.com/hughbe/excel-mapper/pull/115))
- The documentation moved from the README into [`docs/`](docs). ([#132](https://github.com/hughbe/excel-mapper/pull/132))
- Mapping a member again in a class map (`Map(p => p.Name)` twice) returns the map it already has, so settings made in each call add up, instead of replacing it and losing the first call's settings. A member mapped by `AutoMap()`, or as another kind of map, still gets a new map. ([#238](https://github.com/hughbe/excel-mapper/pull/238))
- A column name with white space before or after it, such as "Name " (often in headings, and invisible in Excel), matches a member when no column matches exactly, where it was a missing column. ([#239](https://github.com/hughbe/excel-mapper/pull/239))

### Fixed

- Opening a workbook by path while Excel has it open failed on Windows with "The process cannot access the file because it is being used by another process": the file was opened sharing only reading, and Excel holds it open for writing. It's now opened sharing reading and writing. ([#216](https://github.com/hughbe/excel-mapper/pull/216))
- The result of `ExcelSheet.ReadRows<T>()` and `ReadRowResults<T>()` can be enumerated more than once: each enumeration reads the same rows, from the row after the sheet's position when the method was called. Before, a second enumeration continued where the first stopped, so `rows.Any()` followed by `rows.ToList()` lost the first row. ([#206](https://github.com/hughbe/excel-mapper/pull/206))
- With two columns of the same name, `ExcelHeading.GetColumnIndex("Name_2")` found the second, and a column really named "Name_2" after them was found as "Name_2_2". The heading no longer invents names. A case-sensitive column name (`StringComparison.Ordinal`) wasn't found when a column with the same name in another case came before it. ([#207](https://github.com/hughbe/excel-mapper/pull/207))
- Mapping a nested object inside a dictionary with keys that aren't strings, such as `Map(p => p.ById[5].Street)` for a `Dictionary<int, Address>`, threw `InvalidCastException`. ([#180](https://github.com/hughbe/excel-mapper/pull/180))
- Extra columns on a nested object (`MapExtraColumns(p => p.Details.Extra)`, or `[ExcelExtraColumns]` on a member of a nested type) included the columns read by members outside the nested object, such as the parent's. They now leave out every column read by the type being read, at any depth. ([#166](https://github.com/hughbe/excel-mapper/pull/166))
- `Queue<T>`, `Stack<T>`, `ConcurrentQueue<T>`, `ConcurrentStack<T>`, `ConcurrentBag<T>` and other collections created by passing their items to a constructor that takes `IEnumerable<T>` no longer lose duplicate values: they were built through a `HashSet<T>`, because looking for a constructor taking `ISet<T>` also matched constructors taking `IEnumerable<T>`. Collections whose constructor takes `ICollection<T>` or `IReadOnlyList<T>` are now supported too. These collections also map 9% faster with less allocated, as the list holding the items is reused for each row. ([#161](https://github.com/hughbe/excel-mapper/pull/161))
- Two `ExcelSheet` objects for the same worksheet (for example from calling `ReadSheet(name)` twice) shared the reader's position, so reading from one made the other read the wrong rows, or its heading from the wrong row. Each sheet now keeps its own position. ([#141](https://github.com/hughbe/excel-mapper/pull/141))
- Dates and times with AM/PM written with an ordinary space (`3/4/2024 10:30:15 AM`) were invalid for en-US and similar cultures on ICU-based .NET (Linux, macOS and Windows since .NET 5), whose patterns use a narrow no-break space. ([#139](https://github.com/hughbe/excel-mapper/pull/139))
- Rows after an empty line in a CSV file were silently dropped, a sheet with empty lines above its heading returned no rows, and row ranges counted from the end of a CSV file (such as `..^1`) were off by the number of empty lines. Empty lines at the end of a CSV file are still ignored. ([#137](https://github.com/hughbe/excel-mapper/pull/137))
- A `DataRange` ending after the last row of the sheet mapped the last row twice. ([#137](https://github.com/hughbe/excel-mapper/pull/137))
- A `DataRange` that skips leading columns read values from the wrong columns. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Column matching threw when the `DataRange` didn't include every column; `ExcelHeading.GetColumnIndex(predicate)` (was `GetFirstColumnMatchingIndex`) returned the alphabetically first match. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- The `DataRange` row start was ignored for sheets without a heading; `SkipBlankLines` checked columns outside the `DataRange`. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- `SkipBlankLines` read past the end of the `DataRange`; `ReadRows(startIndex, count)` returned later rows when the reader was already past `startIndex`; CSV sheets reported `VeryHidden`. ([#113](https://github.com/hughbe/excel-mapper/pull/113))
- Sharing a class map between importers on different threads could corrupt results, and kept every sheet it had read in memory. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- Changing a member's columns (for example with `WithColumnName`) after reading kept using the old column. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- Building an error message could read the heading as a side effect. ([#130](https://github.com/hughbe/excel-mapper/pull/130))
- On the netstandard builds, argument exceptions had no parameter name, and `null` arguments to string validation threw `ArgumentException` instead of `ArgumentNullException`.
- Reading columns by name, or a dictionary, from rows without a heading gave `The sheet "" does not have a heading. Use a column index map instead.` for a CSV file, with five wordings across the library. The message now says what needed the heading, names the sheet as other errors do, and says what to do instead: `There's no heading to find columns by name in sheet "People". Choose the columns by index or letter instead.` ([#224](https://github.com/hughbe/excel-mapper/pull/224))
- Errors for a type that can't be created name it as C# does (`List<int>` rather than ``System.Collections.Generic.List`1[System.Int32]``), as other errors do. ([#224](https://github.com/hughbe/excel-mapper/pull/224))
- Changing an array after passing it to `WithColumnNames`, `WithColumnIndices` or `WithSeparators` changed the columns or separators the map used, even after the map was frozen. The maps copy the array. ([#226](https://github.com/hughbe/excel-mapper/pull/226))
- A number given by `[ExcelDefaultValue]`, `[ExcelInvalidValue]` or `[ExcelMappingDictionary]` is converted to the member's number type, or enum, if that doesn't change it, so `[ExcelDefaultValue(0)]` works on a `double`, `long` or `decimal` member. It threw `InvalidCastException` for every empty or invalid cell (and a `decimal` member couldn't have a numeric value at all). A value that can't be the member's type, such as `1.5` for an `int` or `null` for a non-nullable member, throws an `ExcelMappingException` naming the member when the class map is created, instead of an exception for every cell. ([#227](https://github.com/hughbe/excel-mapper/pull/227))
- Two `[ExcelMappingDictionary]` attributes for the same text (or text the member's comparer treats as the same) throw an `ExcelMappingException` naming the member and the text, instead of an `ArgumentException` without either. ([#227](https://github.com/hughbe/excel-mapper/pull/227))
- Reading a dictionary from columns with the same name, such as a row as a `Dictionary<string, string>` when two columns are named "Name", threw an `ArgumentException: An item with the same key has already been added`. It throws an `ExcelMappingException` naming both columns. ([#228](https://github.com/hughbe/excel-mapper/pull/228))
- A dictionary with keys that aren't strings, such as `Dictionary<int, string>`, parses its column names with the importer's culture instead of the machine's, and a name that isn't a valid key throws an `ExcelMappingException` naming the column instead of a `FormatException`. ([#228](https://github.com/hughbe/excel-mapper/pull/228))
- Leaving a `foreach` over `ExcelImporter.ReadSheets()` early left the importer part way through its sheets, so the next `ReadSheet()` returned a later sheet instead of the first. ([#229](https://github.com/hughbe/excel-mapper/pull/229))
- `ExcelRegion`'s reading methods read (or search for) the region's heading when they're called, as `ExcelSheet`'s do, so a missing heading or columns throws then. `ReadRows(sink)` and `ReadRowResults` documented this but threw when the result was enumerated. ([#229](https://github.com/hughbe/excel-mapper/pull/229))
- A member mapped with `Map(...)` whose type can't be read from a cell, such as a `HashSet<string>` (which the collection overloads of `Map` don't cover), failed with "Cannot register a class map with a property that has no Mappers defined." The error names the member and its type, and says what to use instead: `MapCollection<string>(...)` for a collection, `MapDictionary<TValue>(...)` for a dictionary, or a converter or `MapObject(...)` for another type. A class map passed to `ReadRows` without registering it is checked too, when it's first used, instead of every cell being invalid. ([#230](https://github.com/hughbe/excel-mapper/pull/230))
- `WithClassMap(classMap)` ignored a class map that reads the row as a single value (`Map(p => p)`), so the class map then had nothing to map. ([#230](https://github.com/hughbe/excel-mapper/pull/230))
- A fractional number in a cell, such as 2.5, mapped to an integer type gave a message with the number written in the machine's culture ("2,5" on a German machine) and a `FormatException` as its `InnerException`, where the text "2.5" gave an `OverflowException`. Both give an `OverflowException`, and the number is written in the importer's culture. ([#231](https://github.com/hughbe/excel-mapper/pull/231))

### Performance

- An `ExcelMappingException` builds its message when it's first read, so `ReadRowResults` over a file with many invalid or empty cells allocates about a fifth less and is about 10% faster. ([#209](https://github.com/hughbe/excel-mapper/pull/209))
- Dates and times written as ISO 8601 text (`2024-03-04`, `2024-03-04T10:30:15Z`), the most common form in CSV files, are parsed about twice as fast: with the one ISO format the text can match, before the culture's own patterns, rather than trying each format in turn. ([#210](https://github.com/hughbe/excel-mapper/pull/210))
- With native AOT, a generated `ExcelMappingContext` sets members and calls constructors with generated code rather than reflection, which boxed values and allocated an argument array for every member: rows allocate the same as with the JIT (a 10-member class 58 MB instead of 84 MB for 50,000 rows, a struct 53 MB instead of 129 MB), and map 8 to 21% faster. `ExcelTypeRegistrar` has `Setter` and `Constructor` for this, with `ExcelMemberSetter<TOwner, TValue>`, `ExcelConstructor<TOwner>` and `ExcelConstructorArguments<TOwner>`. ([#202](https://github.com/hughbe/excel-mapper/pull/202))
- Whole numbers in text cells, such as CSV, are parsed about 4 times faster: plain digits are tried with .NET's fast integer parser before the default style, which accepts thousands separators and decimal points. CSV columns of `int`, `long`, `byte` and other integer types map about 30% faster, almost as fast as `string` columns, with the same results. ([#197](https://github.com/hughbe/excel-mapper/pull/197))
- Rows that are structs are never boxed: they're created and set in place by compiled setters, instead of by reflection on a boxed copy, which also boxed every member's value. Record structs, nested structs, and single values (`ReadRows<int>()`) aren't boxed either. Mapping 50,000 rows of a 10-member struct is 17% faster and allocates 15.6 MB (23%) less, less than a class, and `ReadRows<int>()` allocates 24 fewer bytes per row. ([#195](https://github.com/hughbe/excel-mapper/pull/195))
- Collections and dictionaries are built by one builder per member type, shared by every sheet and thread without a lock or a copy for each sheet: 5 collection members from CSV map 8% faster with 14% fewer allocations, and dictionaries allocate 9% less. ([#175](https://github.com/hughbe/excel-mapper/pull/175))
- Every member converts its values without boxing, including members with `[ExcelMappingDictionary]` or `WithMapping`, `object`, `IConvertible`, `Uri` and `Version` members, and `IParsable<T>` and other `IConvertible` types, which used to go through a slower untyped path: a class with such members maps about 10% faster. ([#168](https://github.com/hughbe/excel-mapper/pull/168))
- Invalid values no longer throw and catch an exception for every cell: 7x faster with a fallback. ([#121](https://github.com/hughbe/excel-mapper/pull/121))
- Compiled setters and constructors, and fewer per-row and per-cell allocations. ([#121](https://github.com/hughbe/excel-mapper/pull/121), [#127](https://github.com/hughbe/excel-mapper/pull/127))
- `ReadRowResults` costs the same as `ReadRows` for valid data. ([#126](https://github.com/hughbe/excel-mapper/pull/126))
- Classes whose members each read one column are bound to a sheet once and mapped with typed setters, and reading a cell no longer allocates: about 80% fewer allocations and 18% faster for a 10-member class from CSV, and 75% fewer allocations for typed .xlsx cells. ([#142](https://github.com/hughbe/excel-mapper/pull/142))
- Invalid cells are about 17 times cheaper when the exception is used without being thrown, as by custom invalid fallbacks and `ReadRowResults`: the exception is created directly instead of by parsing the value again and catching what's thrown. 50,000 rows with a third of them invalid take 24 ms instead of 415 ms. ([#157](https://github.com/hughbe/excel-mapper/pull/157))
- `WithConverter(value => ...)` converts without boxing: 3 members with converters map 11% faster with 65 fewer bytes per row. ([#155](https://github.com/hughbe/excel-mapper/pull/155))
- Auto-mapping a type is about 5 times faster: each member's attributes are read once, and the mapper to create for each member type is found once, rather than for every importer. Reading a small file with an auto-mapped 10-member class takes 12 µs instead of 58 µs and allocates 18 KB less. ([#153](https://github.com/hughbe/excel-mapper/pull/153))
- The reader each map finds for a sheet is kept by the sheet, rather than in a weak table allocated by every map: reading a small file is 7–10% faster and allocates about 4 KB less for a 10-member type. ([#152](https://github.com/hughbe/excel-mapper/pull/152))
- Elements of lists, arrays and dictionaries are converted without boxing, like single values: split lists map 12% faster with 193 fewer bytes per row, and lists and dictionaries read from several columns 9% faster with 281 fewer. ([#151](https://github.com/hughbe/excel-mapper/pull/151))
- Records and other types created through a constructor pass member values to the constructor without boxing or an argument array: a 10-member record from CSV maps 20% faster with 279 fewer bytes per row, as fast as a class. ([#150](https://github.com/hughbe/excel-mapper/pull/150))
- Numbers are converted without boxing on the netstandard builds too, as on .NET 8: 8 number members from CSV map 16% faster with 189 fewer bytes per row. ([#149](https://github.com/hughbe/excel-mapper/pull/149))
- `TimeSpan`, `DateTimeOffset`, `DateOnly` and `TimeOnly` members, and their nullable forms, are converted without boxing: 8 such members from CSV allocate 16% less (172 fewer bytes per row) and map about 5% faster. ([#148](https://github.com/hughbe/excel-mapper/pull/148))
- Enums and nullable members are converted without boxing too, and each member's pipeline is read from a snapshot rather than through interfaces: a 10-member class from CSV is 12% faster, nullable members 15% faster with 176 fewer bytes per row, and enums 25% faster. Invalid enum values no longer throw and catch an exception on the netstandard2.0 build. ([#147](https://github.com/hughbe/excel-mapper/pull/147))
- Strings, numbers (.NET 8 build), dates, bools and GUIDs are converted without boxing: 136 fewer bytes per row for a 10-member class. ([#146](https://github.com/hughbe/excel-mapper/pull/146))
- Collections and dictionaries are built without a lock per row, without reflection for `Add` methods and constructors, and without throwaway copies (`ImmutableArray`, frozen collections, queues and stacks, and constructors that copy their argument): up to 96 fewer bytes per row. ([#145](https://github.com/hughbe/excel-mapper/pull/145))
- Every class map is bound the same way, including records, nested objects, collections and dictionaries: records are 12% faster with 200 fewer bytes per row. ([#143](https://github.com/hughbe/excel-mapper/pull/143))
- Reading rows does less for each row: the class map is looked up once per read rather than for every row, and the reader's position is checked once. Reading 50,000 narrow CSV rows is about 2–3% faster. ([#232](https://github.com/hughbe/excel-mapper/pull/232))
- A number cell out of its type's range, such as 300 for a `byte`, is found invalid with a range check instead of throwing and catching an `OverflowException`, so a file with many of them reads about 9 times faster, and an error sink gets them without an exception allocated for each. ([#233](https://github.com/hughbe/excel-mapper/pull/233))

### Platform notes

The package contains `net8.0`, `netstandard2.1` and `netstandard2.0` builds. Some features need the `net8.0` build (used by .NET 8 and later):

- Mapping `DateOnly`, `TimeOnly`, `Half`, `Int128`, `UInt128`, `nint`, `nuint`, `BigInteger`, `Complex` and other `IParsable<T>` / `INumberBase<T>` types.
- `.WithNumberStyle(...)` and `.WithFormatProvider(...)` for number types other than the built-in ones, such as `Half` and `BigInteger` (the netstandard builds have them for `int`, `decimal`, `double` and the other built-in number types).
- `.WithFormats(...)` and related methods for `DateOnly` and `TimeOnly`, and mapping `IReadOnlySet<T>` members.

With native AOT (`PublishAot`), read rows with class maps from an `ExcelMappingContext` ([#199](https://github.com/hughbe/excel-mapper/pull/199)). Without one, class maps registered with `RegisterClassMap` whose members are built-in types (numbers, strings, dates, booleans, GUIDs, nullable values and lists of them) map rows, including records and structs, but auto-mapped members of value types, enums and `IParsable<T>` types don't (see [Trimming and Native AOT](docs/trimming.md)). ([#198](https://github.com/hughbe/excel-mapper/pull/198))

The test suite now also runs against the netstandard builds in CI.
