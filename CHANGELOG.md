# Changelog

All notable changes to ExcelMapper (NuGet package [`ExcelDataReader.Mapping`](https://www.nuget.org/packages/ExcelDataReader.Mapping/)) are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/).

## [4.0.0] - Unreleased

4.0 makes mapping faster and more predictable, and adds ways to read real-world spreadsheets:

- **Read messy sheets:** find a heading below titles and notes (`FindHeading`), read part of a sheet or several tables on one sheet (`Region`), and report every invalid cell in a file instead of stopping at the first (`ReadRowResults`).
- **Map more types:** records and constructor-only types, row numbers, the columns no other member reads, and dates and times written as text in more formats.
- **Extend it simply:** typed converters, transformers, fallbacks and column selectors replace the old low-level types.
- **Faster:** compared with 3.0.3, an auto-mapped 10-member class maps 4 times faster, and ExcelMapper's own allocations for it are 93% lower; invalid cells with a fallback map 9 times faster, as they no longer throw and catch exceptions; and auto-mapping a type is nearly 4 times faster. See the [benchmarks](benchmarks/README.md#40-compared-with-303).

4.0 contains breaking changes. Most code compiles unchanged, but some behaviour changed: see [Migrating to 4.0](docs/migrating-to-4.0.md) for what to check when upgrading from 3.x.

### Breaking changes

- `object` and `IConvertible` members, and `object` values in dictionaries, `ExpandoObject` and non-generic collections, receive the value as Excel stores it (`double`, `DateTime`, `bool`, `string`, ...) instead of its text. ([#124](https://github.com/hughbe/excel-mapper/pull/124))
- `WithConverter` replaces the built-in conversion (and any earlier converter) instead of being tried after it, so the converter is used for every cell that isn't empty, whatever the member's type. Before, it was only used for values the built-in conversion couldn't convert for numbers, dates, enums and most other types, but for every value of strings. ([#154](https://github.com/hughbe/excel-mapper/pull/154))
- A fractional number (such as `2.7`) mapped to an integer type is invalid instead of being truncated (.NET 8) or rounded (netstandard), matching text cells. ([#127](https://github.com/hughbe/excel-mapper/pull/127))
- `ReadRow` and `TryReadRow` read the heading first if it hasn't been read, like `ReadRows`, instead of mapping the heading row as data. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- Sheet names are matched case-insensitively by `ReadSheet(name)` and `TryReadSheet(name, ...)`, as in Excel. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Error messages give Excel cell addresses and one-based rows (`at cell B11`, `on row 11`) instead of zero-based row indexes. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- `ExcelRange` is a `readonly struct`; `default(ExcelRange)` (and the value `TryParse` returns on failure) means every row and column instead of an empty range; `Parse` rejects non-ASCII letters, signs, and rows or columns beyond Excel's limits. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- With a `DataRange` that doesn't start at the first column, `ExcelHeading.GetColumnIndex` and `GetColumnName` use positions in the sheet rather than in the range. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Splitting a cell with a trailing separator (`"a,b,"`) includes the trailing empty value, as `string.Split` does, for arrays and lists alike; an empty cell gives no values. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- `RegisterClassMap` replaces a class map that auto-mapping registered implicitly instead of throwing. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- The low-level extension types are internal, replaced by four extension points: `ICellConverter<T>` (convert a cell), `ICellTransformer` (change a cell before it's converted), `ICellFallback<T>` (the value of an empty or invalid cell) and `IColumnSelector` (choose columns). Attributes, class maps and the fluent methods are unchanged, so most code compiles as before. See [Extension types](docs/migrating-to-4.0.md#extension-types) for what replaces each type.
  - Conversion: `ICellMapper`, `CellMapperResult`, `ReadCellResult`, the mappers in `ExcelMapper.Mappers`, `WithMappers`, `[ExcelMapper]` and the `WithConverter` overload whose delegate takes a `ReadCellResult`. `WithConverter(value => ...)` is a method of a member's map, so a delegate that only throws, or returns a type convertible to the member's, compiles. ([#164](https://github.com/hughbe/excel-mapper/pull/164))
  - Transformers and fallbacks: `Abstractions.ICellTransformer`, `IFallbackItem`, the types in `ExcelMapper.Fallbacks` and `ExcelMapper.Transformers`, `WithFallbackItem`, `WithEmptyFallbackItem` and `WithInvalidFallbackItem`; the attributes no longer accept the old types. ([#164](https://github.com/hughbe/excel-mapper/pull/164))
  - Pipelines: `IValuePipeline` and `IValuePipeline<T>`, and the pipelines' `Mappers`, `Transformers`, `EmptyFallback` and `InvalidFallback` properties. A member's map is a `ValueMap<T>`, and the elements or values of a collection are an `ElementMap<T>` (the collection maps' `Pipeline`). Both derive from `ValuePipeline<T, TSelf>`, whose value methods return the map they're called on; the methods for particular types, such as `WithFormats`, are in `ValuePipelineExtensions` (renamed from `IValuePipelineExtensions`). `WithElementMap`/`WithValueMap` take a `Func<ElementMap<T>, ElementMap<T>>`, so lambdas compile unchanged. ([#163](https://github.com/hughbe/excel-mapper/pull/163), [#164](https://github.com/hughbe/excel-mapper/pull/164), [#170](https://github.com/hughbe/excel-mapper/pull/170))
  - Columns: the readers and reader factories (`ExcelMapper.Readers`, `ICellReader`, `ICellReaderFactory`, `ICellsReader`, `ICellsReaderFactory`), `IExcelColumnMatcher`, `WithReaderFactory` and the matcher overloads; use `IColumnSelector` and `WithColumns(selector)`. ([#162](https://github.com/hughbe/excel-mapper/pull/162))
  - Maps: `IMap`, `IToOneMap`, `IOneToOneMap`, `IManyToOneMap`, `ExcelPropertyMap`, `ExcelClassMap.Properties`, the indexer maps, `AutoMapper`, the maps' constructors and `TryGetValue` methods, and the extension classes `IOneToOneMapExtensions`, `IManyToOneMapExtensions` and `IToOneMapExtensions`, whose column methods are now methods of the maps. `TryGetClassMap` returns an `ExcelClassMap`, and `RegisterClassMap(Type, ExcelClassMap)` replaces `RegisterClassMap(Type, IMap)`. ([#162](https://github.com/hughbe/excel-mapper/pull/162), [#165](https://github.com/hughbe/excel-mapper/pull/165))
  - Collections: the collection factories (`ExcelMapper.Factories`, `IEnumerableFactory<T>`, `IDictionaryFactory<TKey, TValue>`, `IMultidimensionalArrayFactory<T>`): ExcelMapper creates the collection for a member's type. ([#160](https://github.com/hughbe/excel-mapper/pull/160))
  - `MappingDictionaryMapperBehavior` moved to the `ExcelMapper` namespace, and is renamed `MappingDictionaryBehavior`. ([#164](https://github.com/hughbe/excel-mapper/pull/164), [#169](https://github.com/hughbe/excel-mapper/pull/169))
- Types are renamed to say what they are: `OneToOneMap<T>` is `ValueMap<T>`, `ManyToOneEnumerableMap<T>` is `CollectionMap<T>`, `ManyToOneDictionaryMap<TKey, TValue>` is `DictionaryMap<TKey, TValue>` (the methods of `OneToOneMapExtensions` are methods of the maps); `FallbackStrategy` is `EmptyValueStrategy`, with `Error` and `DefaultValue` instead of `ThrowIfPrimitive` and `SetToDefaultValue`; `[ExcelUri]` is `[ExcelUriKind]`; `ExcelImporterUtils` is `ExcelImporterExtensions`; and `WithConverter(value => ...)` takes a `Func<string?, T>` instead of `ConvertUsingSimpleMapperDelegate<T>`. Code that uses `var` and lambdas compiles unchanged. See [Renamed types](docs/migrating-to-4.0.md#renamed-types). ([#169](https://github.com/hughbe/excel-mapper/pull/169))
- `WithValueFallback`, `WithEmptyFallback` and `WithInvalidFallback` take a value of the member's type instead of an `object`, so a value of the wrong type is a compile error instead of an `InvalidCastException` when rows are read. ([#170](https://github.com/hughbe/excel-mapper/pull/170))
- Two helper types made public by accident are internal: `CallerArgumentExpressionAttribute` on the netstandard builds (a polyfill, which the compiler ignored) and `ExcelMapper.Utilities.StringComparerUtilities`. ([#167](https://github.com/hughbe/excel-mapper/pull/167))

### Added

- The `Mapping` benchmarks cover auto-mapping, class maps, invalid values, typed numbers, collections, records, row results, typed converters and regions, and can run against an earlier version of the package to compare (`EXCELMAPPER_VERSION=3.0.3`). ([#173](https://github.com/hughbe/excel-mapper/pull/173))

- The elements and values of collections (`WithElementMap`, `WithValueMap`) take the same value methods as a member's map, including converters and fallbacks for a nullable element's underlying type. `WithMapping` accepts a dictionary whose values derive from the member's type, such as a `Dictionary<string, string>` for a `string?` member. ([#170](https://github.com/hughbe/excel-mapper/pull/170))
- Reading a region gives converters, transformers, fallbacks, column selectors and errors the sheet the region was created from, with the region's heading in `CellContext.Heading` and `ColumnSelectorContext.Heading`, rather than a sheet created for the region. [#174](https://github.com/hughbe/excel-mapper/pull/174)
- The package includes XML documentation, so the API's documentation shows in IntelliSense. ([#167](https://github.com/hughbe/excel-mapper/pull/167))
- `WithFormats`, `WithFormatProvider`, `WithOffset` and `WithNumberStyle` on a member's map return the map itself, so other methods such as `MakeOptional()` chain after them; nullable members take converters and fallbacks for their underlying type: `WithConverter(value => int.Parse(value))`, `WithConverter(ICellConverter<int>)`, `WithEmptyFallback(ICellFallback<int>)` and `WithInvalidFallback(ICellFallback<int>)` on an `int?` member. ([#159](https://github.com/hughbe/excel-mapper/pull/159))
- `IColumnSelector` chooses the columns a member is read from, once for each sheet, from a `ColumnSelectorContext` (the sheet and the heading of the rows being read), with a description for error messages. Set it with `WithColumns(selector)`, `[ExcelColumnMatching(typeof(...))]` or `[ExcelColumnsMatching(typeof(...))]`: a single value reads the first column chosen, a collection or dictionary all of them. ([#158](https://github.com/hughbe/excel-mapper/pull/158))
- `ICellTransformer` (in the `ExcelMapper` namespace) changes a cell's value before it's converted, and can return a typed value (`new CellValue(number)`); `ICellFallback<T>` gives the value of an empty or invalid cell with the cell's value, context and the exception, without boxing. Set them with `WithTransformers(...)`, `WithEmptyFallback(fallback)`, `WithInvalidFallback(fallback)`, `[ExcelTransformer]`, `[ExcelEmptyFallback]` and `[ExcelInvalidFallback]`; `CellValue` has constructors for numbers, booleans, dates and durations. ([#156](https://github.com/hughbe/excel-mapper/pull/156))
- `ICellConverter<T>` converts cells to a member's type with the typed cell value (`CellValue`: numbers, dates and booleans from Excel files aren't converted to text) and where the cell is (`CellContext`: sheet, heading, row, column, cell address, member and culture; `new ExcelMappingException(message, context)` reports the cell as an error), returning a `CellConversionResult<T>` (`Success`, `Invalid` with an optional exception created only if it's used, or `NotHandled`). Set it with `[ExcelConverter(typeof(...))]` or `WithConverter(converter)`; a converter for `T` also converts `T?` members, and for a collection it converts each element. Converters run without boxing. ([#155](https://github.com/hughbe/excel-mapper/pull/155))
- Records and types without a parameterless constructor are created through a constructor whose parameters match mapped members; read-only properties can be mapped through constructor parameters. ([#118](https://github.com/hughbe/excel-mapper/pull/118))
- `[ExcelRowNumber]` and `MapRowNumber(...)` set a member to the row's number, as Excel shows it; `[ExcelExtraColumns]` and `MapExtraColumns(...)` fill a dictionary with the columns no other member reads. ([#136](https://github.com/hughbe/excel-mapper/pull/136))
- `ExcelSheet.ReadRowResults<T>()` reports every invalid cell in every row instead of stopping at the first. ([#126](https://github.com/hughbe/excel-mapper/pull/126))
- `ExcelSheet.Region(...)` and `ExcelRegion` read a block of a sheet with its own heading, to read part of a sheet or several tables on one sheet; `WithHeadingAt`, `WithoutHeading` and `WithHeadingSearch` choose the heading. ([#144](https://github.com/hughbe/excel-mapper/pull/144))
- `ExcelSheet.FindHeading<T>()` and `TryFindHeading<T>()` find the heading row of sheets with titles, notes or blank rows above it, as the first row with the columns `T` needs. ([#140](https://github.com/hughbe/excel-mapper/pull/140))
- `ExcelSheet.ValidateHeading<T>()` and `TryValidateHeading<T>()` report every missing column before reading rows. ([#128](https://github.com/hughbe/excel-mapper/pull/128))
- `ExcelImporter.ReadRows<T>(path or stream)` reads the first sheet in one call. ([#129](https://github.com/hughbe/excel-mapper/pull/129))
- `[ExcelColumnLetter("C")]` and `.WithColumnLetter("C")` map columns by Excel letter. ([#129](https://github.com/hughbe/excel-mapper/pull/129))
- `ExcelImporterConfiguration.Culture` sets the culture used for parsing and converting values to text. ([#127](https://github.com/hughbe/excel-mapper/pull/127))
- `ExcelImporterConfiguration.IgnoreSeparatorsInColumnNames` matches `FirstName` to columns such as "First Name"; errors for a missing column suggest a similarly named one. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- `ExcelImporter` constructors that take an `ExcelReaderConfiguration` (passwords, CSV separators, fallback encodings). ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- `[ExcelOffset("+00:00")]` and `.WithOffset(TimeSpan)` choose the offset of `DateTimeOffset` members. ([#131](https://github.com/hughbe/excel-mapper/pull/131))
- `ExcelMappingException.CellAddress`, `ColumnName` and `Member`. ([#117](https://github.com/hughbe/excel-mapper/pull/117), [#130](https://github.com/hughbe/excel-mapper/pull/130))
- `ExcelRange` equality operators, `ToString()` (an Excel address such as `"A1:B10"`) and `$` absolute references. ([#117](https://github.com/hughbe/excel-mapper/pull/117))
- `WithColumnsMatching(Func<string, bool>)`, `WithColumnsMatching(Regex)` and `WithColumnNameMatching(Regex)`. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- Dates and times written as text (in CSV files, for example) are accepted in more formats by default: ISO 8601 (`2024-03-04`, `2024-03-04T10:30:15Z`) and the culture's short date and short date and time for `DateTime` and `DateTimeOffset`, ISO 8601 for `DateOnly`, and the culture's long time and 24-hour times for `TimeOnly`. Set formats with `[ExcelFormats]` or `WithFormats` to accept only those. ([#139](https://github.com/hughbe/excel-mapper/pull/139))
- Numbers in cells without a date format map to `DateTime`, `DateTimeOffset` and `DateOnly` (Excel serial dates), `TimeOnly` (fraction of a day) and `TimeSpan` (days); time cells map to `TimeSpan`; `bool` accepts "yes" and "no". ([#123](https://github.com/hughbe/excel-mapper/pull/123))
- Sheets without a heading can be auto-mapped when columns aren't looked up by name, for example primitives or `[ExcelColumnIndex]` members. ([#119](https://github.com/hughbe/excel-mapper/pull/119))
- `ExcelMappingException` is thrown, instead of `NullReferenceException`, when an empty value can't be assigned to a non-nullable value type. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Trimming annotations for the net8.0 build: the type passed to `ReadRows<T>`, `RegisterClassMap<T>` and `ExcelClassMap<T>`, and types given in attributes, are kept by the trimmer, so mapping works in trimmed apps; reflection-based APIs are marked `[RequiresUnreferencedCode]`/`[RequiresDynamicCode]` so trimmed and AOT apps get warnings where they call them. See [Trimming and Native AOT](docs/trimming.md). ([#138](https://github.com/hughbe/excel-mapper/pull/138))

### Changed

- A value given by `[ExcelMappingDictionary]` that isn't of the member's type is reported when the class map is created, with an `ExcelMappingException` naming the attribute and the member, instead of an `InvalidCastException` when that text is read. ([#168](https://github.com/hughbe/excel-mapper/pull/168))
- The inner exception of the `ExcelMappingException` for an invalid number, date, `Guid`, `bool`, enum or `Uri` has ExcelMapper's own message, naming the value, the type and any formats (for example `The value "abc" isn't a valid Int32.`), instead of the .NET parser's message. Its type is unchanged. ([#157](https://github.com/hughbe/excel-mapper/pull/157))
- Code page encodings are registered automatically; `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` is no longer needed. The netstandard builds now depend on `System.Text.Encoding.CodePages`. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- Trimming only changes text, so cells Excel stores as dates or numbers keep their type. ([#122](https://github.com/hughbe/excel-mapper/pull/122))
- Exceptions thrown by a constructor are wrapped in `ExcelMappingException`. ([#118](https://github.com/hughbe/excel-mapper/pull/118))
- Building an `ExcelMappingException` message no longer reads the sheet's heading. ([#130](https://github.com/hughbe/excel-mapper/pull/130))
- Numbers are parsed the same way on every build. On the netstandard builds, `[ExcelNumberStyle]` now takes effect (previously it was ignored there), and text is parsed with `NumberStyles.Number`, so thousands separators such as `"1,234"` are accepted for integers as they were on .NET 8. Floating-point types also accept exponents such as `"1E5"` on every build (previously only on netstandard). ([#135](https://github.com/hughbe/excel-mapper/pull/135))
- Updated ExcelDataReader to 3.9.0 and ExcelNumberFormat to 1.2.0. ([#115](https://github.com/hughbe/excel-mapper/pull/115))
- The documentation moved from the README into [`docs/`](docs). ([#132](https://github.com/hughbe/excel-mapper/pull/132))

### Fixed

- Extra columns on a nested object (`MapExtraColumns(p => p.Details.Extra)`, or `[ExcelExtraColumns]` on a member of a nested type) included the columns read by members outside the nested object, such as the parent's. They now leave out every column read by the type being read, at any depth. ([#166](https://github.com/hughbe/excel-mapper/pull/166))
- `Queue<T>`, `Stack<T>`, `ConcurrentQueue<T>`, `ConcurrentStack<T>`, `ConcurrentBag<T>` and other collections created by passing their items to a constructor that takes `IEnumerable<T>` no longer lose duplicate values: they were built through a `HashSet<T>`, because looking for a constructor taking `ISet<T>` also matched constructors taking `IEnumerable<T>`. Collections whose constructor takes `ICollection<T>` or `IReadOnlyList<T>` are now supported too. These collections also map 9% faster with less allocated, as the list holding the items is reused for each row. ([#161](https://github.com/hughbe/excel-mapper/pull/161))
- Two `ExcelSheet` objects for the same worksheet (for example from calling `ReadSheet(name)` twice) shared the reader's position, so reading from one made the other read the wrong rows, or its heading from the wrong row. Each sheet now keeps its own position. ([#141](https://github.com/hughbe/excel-mapper/pull/141))
- Dates and times with AM/PM written with an ordinary space (`3/4/2024 10:30:15 AM`) were invalid for en-US and similar cultures on ICU-based .NET (Linux, macOS and Windows since .NET 5), whose patterns use a narrow no-break space. ([#139](https://github.com/hughbe/excel-mapper/pull/139))
- Rows after an empty line in a CSV file were silently dropped, a sheet with empty lines above its heading returned no rows, and row ranges counted from the end of a CSV file (such as `..^1`) were off by the number of empty lines. Empty lines at the end of a CSV file are still ignored. ([#137](https://github.com/hughbe/excel-mapper/pull/137))
- A `DataRange` ending after the last row of the sheet mapped the last row twice. ([#137](https://github.com/hughbe/excel-mapper/pull/137))
- A `DataRange` that skips leading columns read values from the wrong columns. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- Column matching threw when the `DataRange` didn't include every column; `GetFirstColumnMatchingIndex` returned the alphabetically first match. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- The `DataRange` row start was ignored for sheets without a heading; `SkipBlankLines` checked columns outside the `DataRange`. ([#116](https://github.com/hughbe/excel-mapper/pull/116))
- `SkipBlankLines` read past the end of the `DataRange`; `ReadRows(startIndex, count)` returned later rows when the reader was already past `startIndex`; CSV sheets reported `VeryHidden`. ([#113](https://github.com/hughbe/excel-mapper/pull/113))
- Sharing a class map between importers on different threads could corrupt results, and kept every sheet it had read in memory. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- Changing a member's columns (for example with `WithColumnName`) after reading kept using the old column. ([#120](https://github.com/hughbe/excel-mapper/pull/120))
- Building an error message could read the heading as a side effect. ([#130](https://github.com/hughbe/excel-mapper/pull/130))
- On the netstandard builds, argument exceptions had no parameter name, and `null` arguments to string validation threw `ArgumentException` instead of `ArgumentNullException`.

### Performance

- Every member converts its values without boxing, including members with `[ExcelMappingDictionary]` or `WithMapping`, `object`, `IConvertible`, `Uri` and `Version` members, and `IParsable<T>` and other `IConvertible` types, which used to go through a slower untyped path: a class with such members maps about 10% faster. ([#168](https://github.com/hughbe/excel-mapper/pull/168))
- Invalid values no longer throw and catch an exception for every cell: 7x faster with a fallback. ([#121](https://github.com/hughbe/excel-mapper/pull/121))
- Compiled setters and constructors, and fewer per-row and per-cell allocations. ([#121](https://github.com/hughbe/excel-mapper/pull/121), [#127](https://github.com/hughbe/excel-mapper/pull/127))
- `ReadRowResults` costs the same as `ReadRows` for valid data. ([#126](https://github.com/hughbe/excel-mapper/pull/126))
- Classes whose members each read one column are bound to a sheet once and mapped with typed setters, and reading a cell no longer allocates: about 80% fewer allocations and 18% faster for a 10-member class from CSV, and 75% fewer allocations for typed .xlsx cells. ([#142](https://github.com/hughbe/excel-mapper/pull/142))
- Invalid cells are about 17 times cheaper when the exception is used without being thrown, as by custom invalid fallbacks and `ReadRowResults`: the exception is created directly instead of by parsing the value again and catching what's thrown. 50,000 rows with a third of them invalid take 24 ms instead of 415 ms. ([#157](https://github.com/hughbe/excel-mapper/pull/157))
- `WithConverter(value => ...)` converts without boxing: 3 members with converters map 11% faster with 65 fewer bytes per row. ([#155](https://github.com/hughbe/excel-mapper/pull/155))
- Auto-mapping a type is about 5 times faster: each member's attributes are read once, and the mapper to create for each member type is found once, rather than for every importer. Reading a small file with an auto-mapped 10-member class takes 12 µs instead of 58 µs and allocates 18 KB less. ([#153](https://github.com/hughbe/excel-mapper/pull/153))
- The reader each map finds for a sheet is kept by the sheet, rather than in a weak table allocated by every map: reading a small file is 7–10% faster and allocates about 4 KB less for a 10-member type. ([#152](https://github.com/hughbe/excel-mapper/pull/152))
- Elements of lists, arrays and dictionaries are converted without boxing, like single values: split lists map 12% faster with 193 fewer bytes per row, and lists and dictionaries read from several columns 9% faster with 281 fewer. ([#151](https://github.com/hughbe/excel-mapper/pull/151))
- Records and other types created through a constructor pass member values to the constructor without boxing or an argument array: a 10-member record from CSV maps 20% faster with 279 fewer bytes per row, as fast as a class. ([#150](https://github.com/hughbe/excel-mapper/pull/150))
- Numbers are converted without boxing on the netstandard builds too, as on .NET 8: 8 number members from CSV map 16% faster with 189 fewer bytes per row. ([#149](https://github.com/hughbe/excel-mapper/pull/149))
- `TimeSpan`, `DateTimeOffset`, `DateOnly` and `TimeOnly` members, and their nullable forms, are converted without boxing: 8 such members from CSV allocate 16% less (172 fewer bytes per row) and map about 5% faster. ([#148](https://github.com/hughbe/excel-mapper/pull/148))
- Enums and nullable members are converted without boxing too, and each member's pipeline is read from a snapshot rather than through interfaces: a 10-member class from CSV is 12% faster, nullable members 15% faster with 176 fewer bytes per row, and enums 25% faster. Invalid enum values no longer throw and catch an exception on the netstandard2.0 build. ([#147](https://github.com/hughbe/excel-mapper/pull/147))
- Strings, numbers (.NET 8 build), dates, bools and GUIDs are converted without boxing: 136 fewer bytes per row for a 10-member class. ([#146](https://github.com/hughbe/excel-mapper/pull/146))
- Collections and dictionaries are built without a lock per row, without reflection for `Add` methods and constructors, and without throwaway copies (`ImmutableArray`, frozen collections, queues and stacks, and constructors that copy their argument): up to 96 fewer bytes per row. ([#145](https://github.com/hughbe/excel-mapper/pull/145))
- Every class map is bound the same way, including records, nested objects, collections and dictionaries: records are 12% faster with 200 fewer bytes per row. ([#143](https://github.com/hughbe/excel-mapper/pull/143))

### Platform notes

The package contains `net8.0`, `netstandard2.1` and `netstandard2.0` builds. Some features need the `net8.0` build (used by .NET 8 and later):

- Mapping `DateOnly`, `TimeOnly`, `Half`, `Int128`, `UInt128`, `nint`, `nuint`, `BigInteger`, `Complex` and other `IParsable<T>` / `INumberBase<T>` types.
- `.WithNumberStyle(...)` and `.WithFormatProvider(...)` for numeric members (use `[ExcelNumberStyle]` and `ExcelImporterConfiguration.Culture` on the netstandard builds).
- `.WithFormats(...)` and related methods for `DateOnly` and `TimeOnly`, and mapping `IReadOnlySet<T>` members.

The test suite now also runs against the netstandard builds in CI.
